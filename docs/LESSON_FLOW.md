# Guided Lesson UX — концепция (для утверждения)

Цель: превратить набор отдельных режимов (Library → Trace → Complexity → Challenge) в один
связный обучающий сценарий «узнал алгоритм → увидел его в действии → проверил понимание».

Проект уже содержит весь нужный контент (`summary`, `explanation[3]`, `limitation`,
`complexity`, `traits`, `tags`, `useCases`, `examples`), пошаговый trace и мини-квиз «Challenge».
Задача данного этапа — соединить это в путь, а не добавлять новый контент.

---

## 1. Точки входа (откуда стартует урок)

Пользователь попадает в урок из трёх мест, и все они ведут к одному сценарию:

| Точка входа          | Триггер                                 | Что происходит                                                  |
| -------------------- | --------------------------------------- | --------------------------------------------------------------- |
| **Card «Algorithm»** | кнопка `Начать урок` в детали алгоритма | открывает урок для этого алгоритма                              |
| **AdvisorPanel**     | новый сценарий «Хочу понять алгоритм»   | после выбора задачи → открывает урок для топ-алгоритма          |
| **При первом Trace** | онбординг `First trace`                 | предлагает пройти урок как альтернативу свободному исследованию |

Кнопка `Начать урок` — вторичное действие, не заменяет существующие `Visualize / Add to benchmark / Analyze`.
Урок раскрывается **встроенно внутри карточки алгоритма** (вместо/поверх зоны деталей), сохраняя контекст
каталога слева и не открывая новый полноэкранный режим.

---

## 2. Структура урока (5 шагов)

Урок — линейный путь с верхним прогресс-баром и кнопками `Назад` / `Далее`. Пять шагов:

### Шаг 1. «Что это решает» (проблема)

- Показывает `summary` + `useCases` (если есть) — простыми словами: какую задачу закрывает.
- Для sort-алгоритма — пример `examples.default` уже отсортированный слева, вход — справа.
- Никакого кода. Цель — контекст.

### Шаг 2. «Как это работает» (идея)

- Показывает `explanation` как 3 карточки-этапа, анимированные последовательно.
- Заголовок каждой карточки = `explanation[i]`, под ним мини-иллюстрация (SVG для sort — серия
  обмена/вставки; для прочих доменов — схема из текущих моделей).
- Цель — концепция без деталей реализации.

### Шаг 3. «Посмотри в действии» (интерактив)

- Это **существующий** Trace: массив + шаги + `PlaybackBar` + `MetricsPanel`.
- Автозапуск на `examples.default`.
- Подсказки-маячки: на конкретных шагах появляется `Почему это сравнение?` с коротким
  ответом. Включены **на всех режимах**; маячок привязан к типу события
  (`compare` / `write` / `call`).

### Шаг 4. «Проверь себя» (quiz)

- Развитие существующего «Challenge»: 3–4 вопроса по алгоритму.
- Типы вопросов (генерируются из метаданных, не пишутся вручную):
  - **Предскажи следующее событие** — уже существует в «Challenge».
  - **Почему операция** — «Зачем здесь `write`?» с выбором 2–3 объяснений.
  - **Сложность** — «Какая оценка у этого алгоритма?» (проверка понимания Big-O).
  - **Выбор по критерию** — «Что выбрать, если массив почти отсортирован?».
- Ответ всегда с разбором: показать правильное и _почему_ (не просто ✓/✗).
- 80%+ верных → шаг 5. Меньше — вернуться к шагу 3.

### Шаг 5. «Итог» (резюме + следующий шаг)

- Сводка: что узнал, `complexity`, главный `<limitation>`.
- Действия: `Сравнить с референсом` → Compare, `Попробовать худший случай` → Trace с `worstCase`,
  `Смотреть рост` → Complexity.
- Кнопка завершения урока.

---

## 3. Состояние и resume

- Состояние урока (`algorithmId`, текущий шаг, число верных/неверных ответов, время) —
  в `localStorage` по ключу `algoscope:lesson:<algoId>`.
- При повторном открытии урока — предложение `Продолжить с шага N` или `Начать заново`.
- Прогресс-бар наверху: `1/5 … 5/5`, заполнение только после завершения каждого шага.

---

## 4. Адаптация по уровню (отложено на этап 3)

Режимы **Новичок / Средний / Инженер** не входят в первый этап, чтобы не раздувать объём.
На этом этапе урок единый — 5 шагов с подсказками-маячками на всех режимах и quiz из 4 вопросов.
Режимные вариации (длина шагов 1–2, число вопросов, вкл/выкл маячков, вопрос про контракт)
вернутся в этап «Персонализация и повторение».

---

## 5. Что происходит с данными

- Ни один урок не пишет в каталог. `algorithmId` — только ссылка.
- Нет нового контента в `i18n` вручную: вопросы генерируются из `explanation` / `complexity` /
  `traits` / `family`, плюс несколько универсальных шаблонов, переведённых на en/ru.
- Исключение — тексты самого урока и универсальные вопросы, их приходится добавить в `i18n` вручную.

---

## 6. Границы (что урок НЕ делает на этом этапе)

- Не меняет существующие режимы и их контракт.
- Не добавляет алгоритмы в каталог.
- Не трогает WASM-рантаймы и языки.
- Не пишет аналитику — только локальный прогресс.

---

## 7. Утверждённые решения (2026-08-29)

| #   | Решение                              | Выбор                                                                    |
| --- | ------------------------------------ | ------------------------------------------------------------------------ |
| 1   | Количество шагов                     | **5 шагов** (принято)                                                    |
| 2   | Точки входа                          | **три** — карточка, AdvisorPanel, онбординг (на усмотрение разработчика) |
| 3   | Раскрытие урока                      | **встроенный** в карточку (не полноэкранный)                             |
| 4   | Режимы «Новичок / Средний / Инженер» | **отложены** на этап 3 (персонализация)                                  |
| 5   | Порог перехода из quiz               | **80%** верных                                                           |
| 6   | Подсказки-маячки                     | **на всех режимах**                                                      |
